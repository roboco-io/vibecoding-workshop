# 비개발자를 위한 바이브 코딩 워크숍 — 학생 가이드

> AI에게 자연어로 지시하여 문제를 해결하는 전 과정을 직접 체험합니다.

---

## 워크숍 목표

코딩 없이 클로드와 대화하며 **나만의 문제를 정의하고, 해결 방안을 설계하고, 실제 동작하는 결과물**까지 만들어봅니다.

| # | 단계 | 활동 | 산출물 |
|---|------|------|--------|
| 0 | 환경설정 | 도구 설치 및 프로젝트 준비 | 실습 폴더 + GitHub 리포지토리 |
| 1 | 문제 정의 | 채팅으로 브레인스토밍 | 아이디어 마크다운 문서 |
| 2 | PRD 작성 | 심층 인터뷰로 요구사항 구체화 | PRD (제품 요구사항 문서) |
| 3 | 목업 제작 | 아티팩트 + 코드로 시각화 | 동작하는 HTML 목업 |
| 4 | 개발 계획 | 계획 문서 작성 + GitHub 이슈 등록 | 이슈 기반 개발 계획 |
| 5 | 아키텍처 문서화 | Mermaid 다이어그램 + README 업데이트 | 아키텍처 문서 |
| 6 | 튜토리얼 작성 | 바이브 코딩 튜토리얼 + Git 매뉴얼 | 비개발자용 가이드 문서 |

## 워크숍 타임라인

1. State of Vibe Coding — 바이브코딩의 현주소
1. 환경설정
1. 1단계: 문제 정의 (채팅 + 브레인스토밍)
1. 2단계: PRD 작성 (심층 인터뷰)
1. 3단계: 목업 제작 (아티팩트 + 코드)
1. 4단계: 개발 계획 수립 + GitHub 이슈 등록
1. 5단계: 아키텍처 문서화 (Mermaid 다이어그램)
1. 6단계: 튜토리얼 및 Git 매뉴얼 작성
1. 종료

> 휴식은 자유 — 각 단계 사이에 자율로 쉬어가세요

## 용어집

워크숍에서 사용하는 도구와 용어를 먼저 정리합니다.

| 용어 | 설명 |
|------|------|
| **채팅** | 클로드 앱(claude.ai)의 채팅 모드 — 일반 대화, 브레인스토밍에 사용 |
| **코드** | 클로드 앱의 코드 모드 — 파일을 직접 생성·수정할 수 있는 모드 |
| **코워크** | 클로드 앱의 코워크 모드 — 컴퓨터 작업을 클로드가 대신 수행 |
| **아티팩트** | 클로드 앱에서 생성하는 독립 콘텐츠 (문서, 코드, 다이어그램 등) |
| **코드 CLI** | 터미널에서 실행하는 클로드 코드 명령줄 도구 |
| **PRD** | Product Requirements Document — 제품 요구사항 문서 |
| **YOLO 모드** | 클로드 코드가 권한 확인 없이 자동 실행하는 모드 (실습 전용) |

## 0단계: 환경설정

> 클로드 코워크를 사용하여 도구 설치와 설정을 진행합니다.
> "저는 비개발자입니다"를 반드시 알려주세요 — 클로드가 쉽게 안내해줍니다.

### 설치할 도구 목록

| 도구 | 용도 | 비고 |
|------|------|------|
| 클로드 앱 | 채팅·코드·코워크 모드 사용 | [claude.ai](https://claude.ai) |
| 코드 CLI | 터미널에서 클로드 사용 | 강사 안내에 따라 설치 |
| Git CLI | 버전 관리 | 코워크가 설치 도와줌 |
| GitHub CLI (gh) | GitHub 연동 | 코워크가 설치 도와줌 |
| VSCode | 코드 편집기 | 코워크가 설치 도와줌 |

### Step 0-1: 클로드 코워크로 환경설정 요청

클로드 앱에서 **코워크 모드**로 전환한 뒤, 아래 프롬프트를 입력합니다.

```text
저는 비개발자입니다. 바이브 코딩 워크숍을 위해 다음 도구들을 설치해야 합니다.
이미 설치된 것은 건너뛰고, 설치가 필요한 것만 순서대로 진행해주세요.
각 단계마다 제가 해야 할 행동을 쉽게 설명해주세요.

설치할 도구:
- 클로드 코드 CLI
- Git CLI
- GitHub CLI (gh) — 설치 후 로그인까지
- VSCode
- VSCode 클로드 코드 확장기능
```

클로드가 각 도구의 설치 여부를 확인하고, 필요한 것만 설치를 진행합니다.

### Step 0-2: YOLO 모드 설정

코드 모드와 코드 CLI를 자동 실행 모드로 설정합니다.

```text
클로드 코드의 YOLO 모드를 설정해주세요.
코드 모드와 코드 CLI 모두 권한 확인 없이 자동 실행되도록 해주세요.
```

### Step 0-3: 실습용 프로젝트 생성

```text
워크숍 실습용 빈 폴더를 만들어주세요.
폴더 이름은 'my-vibe-project'로 하고,
이 폴더를 GitHub에 프라이빗 개인 리포지토리로 등록해주세요.
```

**확인할 것:**
- 폴더가 생성되었는지
- GitHub에 프라이빗 리포가 만들어졌는지
- `git status` 실행 시 정상 동작하는지

## 1단계: 문제 정의

> **사용 도구:** 클로드 앱 **채팅** 모드

이 단계에서는 클로드와 대화하며 **내 업무에서 해결하고 싶은 문제**를 구체화합니다.

### Step 1-1: 브레인스토밍

강사가 먼저 데모를 진행합니다. 이후 각자 자신의 문제를 가지고 진행합니다.

**프롬프트 — 문제 발견:**

```text
저는 [나의 직무]를 담당하고 있습니다.
매일 반복하는 업무 중에서 가장 시간이 많이 걸리는 것은 [구체적인 업무]입니다.

이 업무를 AI로 자동화하거나 효율화할 수 있는 방법을 함께 고민해주세요.
가능한 해결 방안을 3가지 이상 제안해주시고,
각 방안의 장단점도 함께 알려주세요.
```

**프롬프트 작성 팁:**
- 최대한 **도전적인 문제**를 가져오세요 — 클로드와 함께라면 생각보다 많은 것이 가능합니다
- 막연한 요청보다 **구체적인 상황 설명**이 좋은 결과를 만듭니다
- 결과가 만족스럽지 않으면 **추가 질문**으로 파고드세요

**프롬프트 — 방향 구체화:**

```text
두 번째 방안이 가장 현실적인 것 같아요.
이 방향으로 더 구체적으로 발전시켜주세요.

- 이 해결책이 실제로 동작하려면 어떤 데이터가 필요한가요?
- 비개발자인 제가 직접 만들 수 있는 범위는 어디까지인가요?
- 가장 빠르게 효과를 볼 수 있는 최소 버전(MVP)은 무엇인가요?
```

**프롬프트 — 기술적 실현 가능성 확인:**

```text
이 아이디어를 웹 앱이나 도구로 만든다면,
바이브 코딩(AI에게 자연어로 지시해서 만드는 방식)으로 구현 가능할까요?
어떤 기술 스택이 적합한지, 난이도는 어느 정도인지 알려주세요.
```

### Step 1-2: 아이디어 문서 저장

브레인스토밍이 완료되면 대화 내용을 저장합니다.

```text
지금까지 논의한 내용을 정리해서 마크다운 문서로 만들어주세요.
다음 내용이 포함되어야 합니다:
- 해결하려는 문제
- 선택한 해결 방안
- MVP 범위
- 필요한 기능 목록
```

**저장 방법:** 클로드 앱 대화 메뉴 → **마크다운으로 다운로드**

### Step 1-3: 아이디어 문서를 프로젝트 폴더로 이동

> **사용 도구:** 클로드 앱 **코드** 모드

다운로드한 아이디어 문서를 실습 프로젝트 폴더로 옮깁니다.

```text
다운로드 폴더에 있는 아이디어 문서(방금 다운로드한 마크다운 파일)를
프로젝트 폴더로 이동시켜주세요.
파일 이름은 'ideation.md'로 변경해주세요.
```

## 2단계: PRD 작성

> **사용 도구:** 클로드 앱 **코드** 모드

아이디어를 **제품 요구사항 문서(PRD)**로 발전시킵니다. 클로드가 심층 인터뷰를 통해 요구사항을 구체화합니다.

### Step 2-1: 심층 인터뷰 시작

```text
ideation.md 파일을 읽고, 이 아이디어로부터 프로젝트 PRD를 만들기 위한
심층 인터뷰를 진행해주세요.

한 번에 모든 질문을 하지 말고, 한 가지 주제씩 순서대로 물어봐주세요.
제 답변을 바탕으로 다음 질문을 만들어주세요.

인터뷰에서 다뤄야 할 주제:
- 이 도구/서비스의 사용자는 누구인가
- 핵심 기능과 우선순위
- 성공 기준 (어떻게 되면 성공인가)
- 제약 조건 (시간, 기술, 데이터)
```

**인터뷰 팁:**
- 정답이 없습니다 — 솔직하게 답변하세요
- "잘 모르겠어요"도 괜찮습니다 — 클로드가 선택지를 제안해줍니다
- 답변이 길어도 됩니다 — 상세할수록 좋은 PRD가 나옵니다

### Step 2-2: PRD 생성

인터뷰가 끝나면 클로드가 PRD를 자동 생성합니다.

```text
인터뷰 내용을 바탕으로 PRD를 작성해주세요.
다음 섹션이 포함되어야 합니다:

1. 프로젝트 개요 (한 문장)
2. 배경 및 문제 정의
3. 목표 사용자
4. 핵심 기능 (우선순위별)
5. 비기능 요구사항
6. 성공 지표
7. 제약 사항 및 가정
8. MVP 범위

파일 이름은 PRD.md로 저장해주세요.
```

### Step 2-3: PRD 검토 및 보완

```text
PRD를 한번 검토해주세요.
- 빠진 내용은 없는지
- 모호한 부분은 없는지
- 비개발자인 제가 이해하기 어려운 표현은 없는지
수정이 필요한 부분이 있으면 알려주세요.
```

## 3단계: 목업 제작

### Step 3-1: 아티팩트로 화면 설계

> **사용 도구:** 클로드 앱 **채팅** 모드 (아티팩트 기능)

PRD를 클로드 앱 채팅에 붙여넣고 시각적 목업을 생성합니다.

```text
아래는 제가 만든 PRD입니다.

[PRD.md 내용 붙여넣기]

이 PRD를 기반으로 주요 화면의 목업을 아티팩트로 만들어주세요.
- 메인 화면
- 핵심 기능 화면 1~2개
- 모바일에서도 보기 좋은 반응형으로 만들어주세요

React 컴포넌트로 만들어주세요.
```

**아티팩트 활용 팁:**
- 생성된 목업이 마음에 들지 않으면 **수정 요청**을 하세요
- "이 버튼을 더 크게", "색상을 파란색 계열로" 같은 구체적 피드백이 좋습니다
- 여러 번 반복해서 원하는 모습에 가까워지게 만드세요

**프롬프트 — 목업 수정:**

```text
목업을 수정해주세요:
- 상단 네비게이션 바를 추가해주세요
- 메인 화면에 최근 사용 내역을 보여주는 섹션을 추가해주세요
- 전체적인 색상을 더 밝고 깔끔하게 바꿔주세요
```

### Step 3-2: 코드로 실제 목업 구현

> **사용 도구:** 클로드 앱 **코드** 모드

아티팩트에서 디자인 방향이 정해지면, 실제 동작하는 HTML 목업을 만듭니다.

```text
PRD.md에 기반해서 동작하는 HTML 목업을 만들어줘.
랄프 루프를 사용해서 끝까지 완성해줘.

조건:
- 단일 HTML 파일로 만들어줘 (별도 서버 없이 브라우저에서 바로 열 수 있게)
- Tailwind CSS CDN을 사용해서 깔끔하게 디자인해줘
- 반응형으로 만들어줘
- 샘플 데이터를 넣어서 실제 동작하는 것처럼 보이게 해줘
```

**"랄프 루프"란?**
클로드가 스스로 결과를 검토하고, 부족한 부분을 발견하면 자동으로 수정하는 반복 과정입니다. 완성도 높은 결과물이 나올 때까지 자동으로 반복합니다.

### Step 3-3: 목업 확인 및 피드백

```text
만든 목업을 브라우저에서 열어서 확인해보고 싶어요.
어떻게 하면 되나요?
```

생성된 HTML 파일을 브라우저에서 열어 확인합니다. 수정이 필요하면:

**프롬프트 — 피드백 반영:**

```text
목업을 확인했는데 몇 가지 수정해주세요:
- [구체적인 수정 사항 1]
- [구체적인 수정 사항 2]
- [구체적인 수정 사항 3]
```

## 4단계: 개발 계획 수립

> **사용 도구:** 클로드 앱 **코드** 모드

완성된 PRD와 목업을 바탕으로, 이 프로젝트를 실제로 개발하기 위한 계획을 세웁니다.

### Step 4-1: 개발 계획 문서 작성

```text
이 프로젝트를 개발자들이 실제로 개발할 수 있도록 계획 문서를 작성해줘.

계획 문서에는 다음이 포함되어야 해:
- 기술 스택 추천 (프론트엔드, 백엔드, 데이터베이스)
- 개발 단계별 작업 목록
- 각 작업의 예상 난이도와 우선순위
- 작업 간 의존성 (어떤 작업이 먼저 완료되어야 하는지)
- MVP와 향후 확장 기능의 구분

파일 이름은 development-plan.md로 저장해줘.
```

### Step 4-2: GitHub 이슈 등록

```text
계획 문서의 각 작업을 gh cli를 사용해서 GitHub 이슈로 등록해줘.

각 이슈에는 다음이 포함되어야 해:
- 작업 배경 (왜 이 작업이 필요한지)
- 작업 내용 (무엇을 해야 하는지)
- 인수 조건 (어떻게 되면 완료인지)
- 다른 작업과의 의존성 (선행 작업이 있다면 이슈 번호로 연결)

이슈에 적절한 라벨도 붙여줘 (예: MVP, enhancement, frontend, backend 등)
```

**이슈 등록이 중요한 이유:**
- 개발자에게 작업을 넘길 때 체계적으로 전달할 수 있습니다
- 각 작업의 진행 상황을 추적할 수 있습니다
- "이슈 #3을 해결해줘"처럼 AI에게 구체적으로 지시할 수 있습니다

### Step 4-3: 결과 확인

```text
등록된 GitHub 이슈 목록을 보여줘.
이슈 간 의존성이 제대로 연결되어 있는지 확인해줘.
```

## 5단계: 아키텍처 문서화

> **사용 도구:** 클로드 앱 **코드** 모드

프로젝트의 전체 구조를 시각적으로 정리합니다. 개발자가 프로젝트를 이해하는 데 필수적인 문서입니다.

### Step 5-1: 아키텍처 문서 생성

```text
이 프로젝트의 아키텍처 문서를 생성해줘.
다이어그램은 mermaid로 그려줘.
리드미(README.md)도 업데이트해줘.

아키텍처 문서에 포함할 내용:
- 시스템 전체 구조 다이어그램
- 주요 컴포넌트 간 관계
- 데이터 흐름
- 사용하는 기술 스택
```

**Mermaid란?**
코드로 다이어그램을 그리는 도구입니다. GitHub에서 자동으로 렌더링되어, 별도 이미지 파일 없이도 다이어그램을 볼 수 있습니다.

## 6단계: 튜토리얼 및 매뉴얼 작성

> **사용 도구:** 클로드 앱 **코드** 모드

오늘 진행한 전체 과정을 다른 비개발자도 따라할 수 있는 튜토리얼로 정리합니다.

### Step 6-1: 바이브 코딩 튜토리얼 작성

```text
지금까지 진행한 내용들을 비개발자를 위한 바이브 코딩 튜토리얼로 만들어줘.

포함할 내용:
- 각 단계별로 무엇을 했는지
- 어떤 프롬프트를 사용했는지
- 어떤 결과물이 나왔는지
- 비개발자가 따라할 수 있도록 쉽게 설명해줘
```

### Step 6-2: 비개발자를 위한 Git 매뉴얼 작성

```text
비개발자를 위한 깃 매뉴얼을 만들어줘.
클로드 코드에서 사용하는 프롬프트를 중심으로 작성해줘.

포함할 내용:
- 깃이 무엇인지 간단한 설명
- 클로드 코드에서 깃 작업을 요청하는 프롬프트 예시
  - 변경사항 확인하기
  - 커밋하기
  - 푸시하기
  - 브랜치 만들기
- 자주 발생하는 문제와 해결 프롬프트
```

## AI와 대화하는 핵심 패턴

워크숍에서 배운 패턴을 다른 업무에도 적용할 수 있습니다.

### 패턴 1: 역할 + 맥락 + 출력형식 지정

```text
당신은 [역할]입니다.
[배경 상황 설명]
[원하는 결과물의 형식]으로 작성해주세요.
```

**예시:**

```text
당신은 10년 경력의 UX 기획자입니다.
저희 회사는 B2B SaaS를 운영하고 있고, 고객 문의가 월 500건입니다.
고객 문의를 자동 분류하는 시스템의 화면 설계를 표 형태로 정리해주세요.
```

### 패턴 2: 단계적 질문 (심층 인터뷰)

```text
[주제]에 대해 심층 인터뷰를 진행해주세요.
한 번에 한 가지 질문만 하고, 제 답변을 바탕으로 다음 질문을 만들어주세요.
```

**예시:**

```text
우리 팀의 주간 보고 프로세스를 개선하고 싶어요.
현재 상황을 파악하기 위해 저에게 심층 인터뷰를 해주세요.
한 번에 한 가지 질문만 하고, 제 답변을 바탕으로 다음 질문을 만들어주세요.
```

### 패턴 3: 검수 루프 (결과 품질 높이기)

```text
[결과물]을 만들어주세요.
완성 후 스스로 검토해서 부족한 점을 수정해주세요.
```

**예시:**

```text
이 제안서 초안을 검토해주세요.
- 논리적 흐름에 빈틈은 없는지
- 설득력이 부족한 부분은 없는지
- 오탈자나 어색한 표현은 없는지
문제가 있으면 수정본을 만들어주세요.
```

### 패턴 4: 문제 해결 (트러블슈팅)

```text
[현재 상황]인데 [원하는 결과]가 나오지 않습니다.
[시도한 것]을 했는데 [발생한 문제]가 생겼습니다.
어떻게 해결할 수 있을까요?
```

**예시:**

```text
클로드에게 월간 매출 보고서 양식을 만들어달라고 했는데,
결과가 너무 일반적이에요.
우리 회사 양식에 맞게 만들려면 어떻게 요청해야 할까요?
```

### 클로드 앱 모드

| 모드 | 용도 | 사용 시점 |
|------|------|-----------|
| **채팅** | 대화, 브레인스토밍, 질문 | 아이디어 구상, 문서 초안 |
| **코드** | 파일 생성·수정, 코드 실행 | PRD 작성, 목업 구현 |
| **코워크** | 컴퓨터 작업 대행 | 환경설정, 도구 설치 |
| **아티팩트** | 독립 콘텐츠 생성 | UI 목업, 다이어그램 |

### 클로드 코드 CLI

| 명령어 | 용도 |
|--------|------|
| `claude --dangerously-skip-permissions` | YOLO 모드로 실행 |
| `/compact` | 대화가 길어졌을 때 컨텍스트 압축 |
| `/clear` | 대화 초기화 (단계 전환 시) |

### GitHub CLI

| 명령어 | 용도 |
|--------|------|
| `gh auth login` | GitHub 로그인 |
| `gh auth status` | 로그인 상태 확인 |
| `gh issue list` | 이슈 목록 확인 |
| `gh repo view --web` | GitHub 리포지토리를 브라우저에서 열기 |

## 트러블슈팅

| 문제 | 해결 |
|------|------|
| 클로드가 질문을 이해 못함 | 더 구체적으로 상황을 설명하세요. "저는 [직무]이고, [상황]에서 [원하는 것]을 하고 싶어요" |
| AI 결과물 품질이 낮음 | **이것이 핵심 학습 포인트** — 역할·맥락·형식을 지정하고, 피드백으로 반복 개선하세요 |
| 코워크가 작업을 잘못함 | 작업을 더 작은 단위로 나눠서 요청하세요 |
| 도구 설치가 안 됨 | TA에게 도움을 요청하세요 |
| 컨텍스트가 길어져 응답이 느림 | `/compact` 또는 `/clear` 후 재시작 |
| GitHub 이슈 등록 실패 | `gh auth status`로 로그인 상태를 먼저 확인하세요 |
| 진도가 느림 | **완주보다 깊이** — 현재 단계에 집중하세요 |
