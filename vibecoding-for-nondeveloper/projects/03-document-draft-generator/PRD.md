# PRD: 문서·보고서 초안 생성기

> 비개발자 바이브 코딩 프로젝트 #3 | 전 직군 공통 | Claude Project + 검수 루프 패턴

## 1. 배경

비개발자 설문에서 **문서(기획·제안·보고)가 주 산출물인 응답자가 92%(11명)** 로 압도적이다. 사용 빈도가 매일 이상인 AI 사용자는 75%이고, 응답자의 83%가 "AI 결과 품질이 들쑥날쑥하다", 58%가 "결국 내가 다 고쳐야 한다"고 답했다.

문제의 본질은 AI 자체가 아니라 **요청 방식의 비일관성**이다. 동일한 사람이 같은 문서를 작성해도 매번 다른 프롬프트, 다른 맥락, 다른 톤으로 시작하니 산출물 품질이 매번 달라진다. 회사 표준 문서(PRD·제안서·주간 보고서)는 구조가 정해져 있는데, 그 구조를 매번 AI에게 새로 설명하고 있는 셈이다.

이 프로젝트는 **회사 표준 템플릿 + 인터뷰 퍼스트 패턴 + 자가 비판 검수 루프**를 한 워크플로우에 묶어, "한 줄 아이디어"에서 "검토 가능한 초안"까지의 거리를 단축한다.

## 2. 목표

### 핵심 목표

회사 표준 문서 유형(PRD, 제안서, 주간 보고서, 회의록, 기획서)별로 **재사용 가능한 Claude Project**를 만들어, 한 줄 입력에서 구조화된 초안까지의 생성을 표준화한다.

### 성공 기준

| 기준 | 목표 |
|------|------|
| 문서 초안 작성 시간 | 평균 2시간 → 30분 (75% 단축) |
| 회사 톤앤매너 일관성 | 사람이 손대지 않아도 80%+ 일치 |
| 첫 초안 그대로 검토 통과율 | 50%+ (나머지는 부분 수정) |
| 누락 항목 자동 감지 (자가 비판) | 작성된 모든 문서에 적용 |

### Non-Negotiable

- 사실 단정 금지 — 데이터 미확보 항목은 "**[확인 필요]**" 명시
- 외부 발송 문서는 **반드시 사람 최종 검토** 후 발신

## 3. 사용자

| 항목 | 내용 |
|------|------|
| 주 사용자 | 전 직군 (기획·영업·운영·경영지원·디자인) |
| 사용 빈도 | 주 1~3회 |
| 핵심 문서 유형 | PRD, 제안서, 주간 보고서, 기획서, 회의록 |

## 4. 핵심 기능

### 4-1. 회사 표준 템플릿 학습

- 문서 유형별 샘플 5~10개 Claude Project에 업로드
- 회사 톤·구조·필수 섹션을 봇이 자동 추출

### 4-2. 인터뷰 퍼스트 패턴

"PRD 써줘"가 아닌 **"PRD를 쓰려고 한다. 필요한 질문을 5~10개 해줘"**:
- 사용자 답변이 누락 없이 입력되도록 강제
- 컨텍스트 부족으로 인한 환각 감소
- 답변 자체가 향후 재사용 가능한 메모로 누적

### 4-3. 구조화된 초안 생성

- 답변 기반으로 표준 섹션에 맞춰 초안 생성
- 회사 톤앤매너 자동 적용
- Markdown Artifact로 출력 → 시각적 검토 용이

### 4-4. 자가 비판 검수 루프

초안 생성 직후 같은 봇에게 자기 검토 요청:
- **논리 결함**: 인과·근거 누락
- **누락 항목**: 표준 섹션 중 비어 있는 부분
- **사실 단정**: 출처·근거 없이 단정한 문장
- **톤 일관성**: 회사 톤에서 벗어난 표현

### 4-5. 재사용 프롬프트 키트

- 문서 유형별 프롬프트 묶음 (생성 + 검수 + 보강)
- 한 번 만들면 팀 공유 → 팀 단위 품질 표준화

## 5. 워크플로우

```
[1회 셋업]
  문서 유형 선정 (PRD·제안서·보고서 등)
       ↓
  회사 샘플 5~10개 Claude Project 업로드
       ↓
  시스템 프롬프트: 구조·톤·필수 섹션 정의

[일상 사용]
  한 줄 아이디어 입력
       ↓
  인터뷰 퍼스트: 5~10개 질문 자동 생성
       ↓
  답변 입력 → 초안 Artifact 생성
       ↓
  자가 비판 프롬프트: 논리·누락·단정·톤 검토
       ↓
  수정 반영 → 최종 초안

[팀 확산]
  완성된 프롬프트 키트 → 팀 공유
       ↓
  팀원이 동일 Project 복제 → 사용
```

## 6. 데이터 및 입력

| 입력 | 형식 | 비고 |
|------|------|------|
| 회사 샘플 문서 | Markdown/Word/PDF | 문서 유형당 5~10개 |
| 회사 톤앤매너 가이드 | Markdown | 있다면 업로드, 없으면 샘플에서 자동 추출 |
| 한 줄 아이디어 | 텍스트 | 시작점 |
| 인터뷰 답변 | 텍스트 | 누적 보관 |

## 7. 산출물

| # | 산출물 | 형태 |
|---|--------|------|
| 1 | 문서 유형별 Claude Project (3~5개) | claude.ai |
| 2 | 인터뷰 퍼스트 프롬프트 템플릿 | Markdown |
| 3 | 자가 비판 검수 프롬프트 | Markdown |
| 4 | 회사 톤앤매너 가이드 (도출본) | Markdown |
| 5 | 프롬프트 키트 (팀 공유용) | Markdown 묶음 |

## 8. 제약사항

| 제약 | 대응 |
|------|------|
| 회사 기밀 문서 업로드 정책 | 익명화·요약 후 학습, 기밀 정보는 분리 |
| 외부 발송 문서 책임 소재 | 사람 최종 검토 절차 명시 |
| 회사 톤이 명시되지 않은 경우 | 샘플 5개로 톤 자동 도출 후 가이드 문서화 |

## 9. 검증 (자가 비판 루프)

```
초안 생성
   ↓
같은 봇에게 자기 비판 요청
   ↓
   ├─ 논리 결함 표시
   ├─ 누락 섹션 표시
   ├─ 사실 단정 문장 표시
   └─ 톤 위반 표현 표시
   ↓
수정·보강
   ↓
최종 검토자(사람) 승인
```

**핵심 원리**: AI가 생성한 결과는 AI에게 다시 검토시킨다. 같은 모델이라도 "생성 모드"와 "비판 모드"의 출력은 다르다.

## 10. Non-Goals

| 항목 | 이유 |
|------|------|
| 외부 자동 발송 | 검토 누락 시 신뢰 손상 위험 |
| 다국어 최종본 단독 생성 | 영문은 원어민 검토 별도 권장 |
| 디자인 레이아웃 자동화 | 텍스트 초안에 집중, 레이아웃은 별도 도구 |
| 데이터 시각화 자동 생성 | 시각화는 프로젝트 #4(예산 시트)에서 분리 처리 |

## 11. 확장 가능성

- **회의록 자동 액션 아이템 추출**: 회의록 유형 Project에 액션 아이템 자동 분리 프롬프트 추가
- **이메일 톤 변환기**: 같은 패턴을 이메일·Slack 메시지로 확장
- **다국어 초안 변환**: 한국어 초안 → 영문 1차 번역 (검토 전제)
- **문서 간 일관성 검증**: PRD ↔ 제안서 ↔ 보고서 내용 충돌 자동 감지
