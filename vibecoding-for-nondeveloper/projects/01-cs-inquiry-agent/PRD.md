# PRD: CS 문의 자동 분류 & 대응 에이전트

> 비개발자 바이브 코딩 프로젝트 #1 | 영업·CS·운영 직군 대상 | Claude Project 기반

## 1. 배경

비개발자 사전 설문(12명)에서 영업·CS·운영 직군이 42%(5명)로 최다였으며, 이 그룹이 공통으로 꼽은 병목 업무는 **고객 문의 1차 분류와 응답 초안 작성**이다. 한 응답자는 매우 구체적인 에이전트 흐름을 직접 제출했다:

> "솔루션 사양을 학습시킨 봇이 문의 원인(사양/버그)을 판단해주고, 누적 문의에서 개발 우선순위와 대응 프로세스 개선점을 도출해주고, 진행 중 문의 상태까지 체크해주면 좋겠다."

CS 담당자는 매일 수십 건의 문의를 받지만, 같은 패턴의 질문에 매번 처음부터 답하고, 사양/버그 구분을 위해 매뉴얼을 다시 뒤지며, 누적 데이터에서 인사이트를 뽑을 시간이 없다. AI 활용 빈도는 높으나(75%가 매일 이상 사용) **결과 품질이 들쑥날쑥하다는 어려움이 83%** 로 1위 — 즉, 일회성 챗 사용으로는 안정적 품질이 안 나온다.

## 2. 목표

### 핵심 목표

CS 담당자가 신규 문의를 받았을 때 **분류 → 응답 초안 → 인사이트 누적**까지 한 흐름에서 처리하는 Claude Project를 구축한다.

### 성공 기준

| 기준 | 목표 |
|------|------|
| 신규 문의 1건당 처리 시간 | 평균 15분 → 5분 (66% 단축) |
| 분류 정확도 (사양/버그/사용자 실수 구분) | 80%+ |
| 응답 초안 그대로 발송 가능 비율 | 50%+ (나머지는 부분 수정) |
| 주간 인사이트 리포트 자동 생성 | 가능 |

### Non-Negotiable

- 고객 응답은 **반드시 사람 검토 후 발송** (Human-in-the-loop)
- 고객 개인정보는 익명화 후 업로드

## 3. 사용자

| 항목 | 내용 |
|------|------|
| 주 사용자 | CS·운영 담당자 (코딩 미경험) |
| 보조 사용자 | 영업·운영 매니저 (인사이트 리포트 소비자) |
| 사용 빈도 | 매일 (문의 발생 시마다) |
| 사용 환경 | 회사 노트북 (Windows 75%), 브라우저 |

## 4. 핵심 기능

### 4-1. 솔루션 사양 학습 (Knowledge Base)

- 제품 매뉴얼, FAQ, 릴리스 노트, 사양 문서를 Claude Project에 업로드
- 신규 기능 추가 시 문서만 갱신하면 봇 동작 즉시 반영

### 4-2. 문의 1차 분류

신규 문의 텍스트 입력 시 자동 출력:
- **유형**: 사양 / 버그 / 사용자 실수 / 신규 요구
- **근거**: 매뉴얼 몇 페이지·어느 항목 기반인지 인용
- **확신도**: 상/중/하 (하인 경우 "추가 확인 필요" 표시)

### 4-3. 응답 초안 생성

- 회사 톤앤매너 학습 (과거 응답 사례 5~10개 업로드)
- 분류 결과 기반 응답 초안 자동 작성
- 사양 문의면 → 해당 매뉴얼 링크 포함
- 버그 의심이면 → 재현 단계 질문 템플릿 포함

### 4-4. 누적 문의 인사이트 리포트

- 주/월 단위 익명화 문의 CSV 업로드 → 자동 분석
- 출력: 빈도 Top 5 / 신규 이슈 패턴 / 개발 우선순위 제안 / 대응 프로세스 개선점

### 4-5. 진행 중 문의 상태 체크

- 처리 중 문의 목록 텍스트 입력 → 지연·재촉·에스컬레이션 후보 자동 추출
- Slack/이메일용 follow-up 메시지 템플릿 생성

## 5. 워크플로우

```
[1회 셋업]
  사양 문서·FAQ·과거 응답 사례 정리
       ↓
  Claude Project 생성 + 시스템 프롬프트 설정
       ↓
  분류·응답·인사이트 출력 형식 템플릿 고정

[일상 사용]
  신규 문의 텍스트 붙여넣기
       ↓
  분류 + 응답 초안 자동 생성
       ↓
  사람 검토·수정 → 발송
       ↓
  익명화 후 누적 데이터에 추가

[주간 운영]
  누적 CSV → 인사이트 리포트 자동 생성
       ↓
  개발팀·운영팀 공유
```

## 6. 데이터 및 입력

| 입력 | 형식 | 비고 |
|------|------|------|
| 솔루션 매뉴얼 | PDF/Markdown | Claude Project Knowledge |
| FAQ | 텍스트/CSV | 동일 |
| 과거 응답 사례 | 텍스트 (5~10건) | 톤앤매너 학습용 |
| 신규 문의 | 텍스트 (붙여넣기) | 익명화 필수 |
| 누적 문의 이력 | CSV | 익명화 필수 |

## 8. 제약사항

| 제약 | 대응 |
|------|------|
| 데이터 업로드 정책 불확실 (설문 33%) | 익명화 가이드 필수, 더미 데이터로 1차 검증 |
| 회사 관리 노트북 보안 정책 | 로컬 설치 없이 브라우저 기반 claude.ai 사용 |
| 실시간 시스템 연동 불가 | 1단계는 복붙 워크플로우, 2단계에서 Slack/Help Desk 통합 검토 |

## 9. 검증 (Human-in-the-loop)

```
AI 분류·응답 초안 → 담당자 검토 → 수정 → 발송 → 결과 기록
                ↑                              ↓
                └──── 오분류 사례 누적 ───── 프롬프트·문서 보강
```

**오분류 사례 5건 누적 시 시스템 프롬프트 재튜닝**을 운영 루틴에 포함한다.

## 10. Non-Goals

| 항목 | 이유 |
|------|------|
| 이메일·Slack 자동 발송 | 검토 없는 자동 응답은 사고 위험 |
| 고객 식별 정보 업로드 | 보안 정책 위반 가능 |
| 외부 CRM 시스템 직접 연동 | 1단계 범위 초과 (2단계 확장 검토) |
| 다국어 자동 응답 | 영문 응답 필요 시 별도 프롬프트로 분리 |

## 11. 확장 가능성

- **Slack 봇 통합**: Zapier/Make로 신규 문의 트리거 자동화
- **Help Desk 연동**: Zendesk·Freshdesk webhook 활용
- **개발자 대응 봇**: 버그 분류 결과를 이슈 트래커 자동 등록
