# 계획서 필수 섹션 템플릿

아래 10개 섹션은 `migration-plan.md`에 **반드시 포함**해야 한다. 9개 팀 리뷰에서 발견된 공통 약점을 방지하기 위한 필수 항목이다.

## 섹션 1: 프로젝트 현황 분석

```markdown
## 1. 프로젝트 현황 분석

### 1.1 기술 스택
| 구분 | 현재 | 비고 |
|------|------|------|

### 1.2 코드 규모
| 항목 | 수치 |
|------|------|
| 총 파일 수 | N개 |
| 코드 라인 수 | N줄 |
| 테스트 파일 수 | N개 |
| 대형 파일 (1000줄+) | N개 |

### 1.3 현재 상태 진단
| 영역 | 현재 상태 | 목표 상태 | 갭 | 영향 |
|------|----------|----------|-----|------|

### 1.4 보유 자산
- 이미 갖춰진 것 (CLAUDE.md, 테스트, CI 등)

### 1.5 기술 부채
| 항목 | 건수 | 심각도 | 비고 |
|------|------|--------|------|
```

## 섹션 2: 전환 전후 비교

**정량적** 전후 비교 표를 반드시 포함한다.

```markdown
## 2. 전환 전후 비교

| 항목 | 전환 전 | 목표 | 측정 방법 |
|------|--------|------|----------|
| CLAUDE.md | 없음/기본 | 완비 (N줄+) | 파일 존재 + 필수 섹션 |
| ADR | 0건 | N건 | docs/adr/ 파일 수 |
| 테스트 커버리지 | N% | N%+ | CI 리포트 |
| CI 품질 게이트 | 없음 | lint + test + coverage | CI 설정 |
| 스킬 | 0개 | N개 | .claude/skills/ |
```

## 섹션 3: 단계별 계획

Step 단위 테이블 형식으로 작성한다. Phase 구성은 [project-guidelines.md](project-guidelines.md)의 프로젝트 유형별 가이드를 따른다.

```markdown
## 3. 단계별 계획

### Phase 1: 문서화

| Step | 작업 | 산출물 | 의존성 | 인수조건 |
|------|------|--------|--------|---------|
| 1-1 | CLAUDE.md 작성 | CLAUDE.md | 없음 | 필수 섹션 5개 포함 |
| 1-2 | ADR 작성 (ADR-001~005) | docs/adr/*.md | 없음 | 각 ADR에 Context/Decision/Consequences |
| 1-3 | 코드 컨벤션 문서 | CONVENTIONS.md | 없음 | 린트 규칙과 일치 |
| 1-4 | 도메인 용어집 | docs/glossary.md | 없음 | 핵심 용어 20개+ |
| 1-5 | 아키텍처 문서 | ARCHITECTURE.md | 1-1 | 디렉토리 구조, 의존성 맵 |

> Step 1-1 ~ 1-4는 의존성 없음 → **동시 병렬 실행 가능**
> Step 1-5는 1-1 완료 후 진행
```
