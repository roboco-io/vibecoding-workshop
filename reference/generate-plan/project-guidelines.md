# 프로젝트 유형별 가이드라인

프로젝트 성격에 따라 Phase 구성과 전략을 달리한다. 9개 팀 리뷰에서 추출한 교훈을 반영한다.

## Phase 구성 템플릿

### 레거시 전환 프로젝트

```
Phase 1: 문서화 (CLAUDE.md, ADR, 컨벤션, 용어집)
Phase 2: 이슈 체계화 (GitHub/Jira 이슈 생성, 우선순위)
Phase 3: 스킬 생성 (프로젝트 전용 스킬 설계)
Phase 4: 테스트 인프라 (테스트 프레임워크, CI 품질 게이트)
Phase 5: 보안 리뷰 (OWASP Top 10, 크리티컬 이슈 수정)
Phase 6: 최종 검증 및 팀 온보딩
```

### 신규 개발 프로젝트

```
Phase 1: 프로젝트 기반 구축 (CLAUDE.md, ADR, 모노레포/구조 결정)
Phase 2: OpenSpec 명세 (핵심 기능별 스펙 문서)
Phase 3: 테스트 인프라 + CI/CD
Phase 4: 주차별 개발 계획 (이슈 상세, 담당자, 인수조건)
Phase 5: 보안 + 성능 기준선
Phase 6: 배포 + 검증
```

### 운영 중 개선 프로젝트

```
Phase 1: 문서화 (현행 코드 분석, CLAUDE.md)
Phase 2: 테스트 안전망 확보 (기존 테스트 안정화 + 핵심 모듈 테스트)
Phase 3: 이슈 체계화 + 스킬 생성
Phase 4: 점진적 개선 (기술 부채 우선순위별 해소)
Phase 5: CI 품질 게이트 + 보안 리뷰
Phase 6: 최종 검증
```

## 유형별 전략

### 레거시 전환

- **Strangler Fig 패턴** 적용 권장 (OX, 웹개발팀 OK3 사례)
- 기존 테스트 안정화를 신규 테스트보다 먼저 (OfficeKeeper5 교훈)
- 린터 도입 시 점진적 확대: 최소 규칙부터 → 단계적 추가 (Safebox Ruff 사례)
- 대형 파일 분할은 2단계로: 핵심 모듈 먼저 → 나머지 (CrossViewer 교훈)

### 신규 개발

- **주차별 이슈 상세** 작성 권장: 담당자 + 인수조건 (오피스노트 사례)
- OpenSpec으로 비즈니스 규칙 명시 (코드만으로 파악 어려운 규칙)
- 데이터 마이그레이션이 있으면 3회 이상 리허설 (오피스노트 교훈)
- 범위 제외를 명확히 하여 크리프 방지

### 운영 중 개선

- **안전 인프라 우선**: 커버리지 목표보다 인프라 구축 먼저 (Safebox 사례)
- Phase 순서를 프로젝트 상황에 맞게 조정 + 근거 명시 (Office Agent Knowledge Hub 사례)
- 프로덕션 영향 최소화: baseline 전략, 기능 플래그 활용

### 멀티서비스/멀티플랫폼

- **팀 레벨 통합 로드맵** 필수 (Office Agent 교훈)
- 서비스 간 계약(API, 메시지 스키마)을 OpenSpec으로 문서화
- 전환 순서: 독립성 높은 서비스부터 → 의존성 있는 서비스 순
