컨텍스트 엔지니어링

정의 AI가 프로젝트를 이해할 수 있도록 컨텍스트를 코드처럼 관리한다 (CLAUDE.md, /init)
현재의 마찰

설문 60%가 'AI에게 코드베이스를 효과적으로 전달하지 못함'을 도입 1위 장애물로 꼽았다. 컨텍스트는 사람이 매번 채팅에 다시 붙여넣고, 신입은 코드를 읽어 추측한다.

AI Level Boost
  1. Friction 제거: /init이 프로젝트 구조를 자동 스캔해 CLAUDE.md 초안 생성
  2. 인터뷰 퍼스트 패턴이 빠진 맥락을 AI가 질문해 채운다
  3. CLAUDE.md가 모든 후속 세션의 자동 컨텍스트
  4. 🎓 학습 가속: AI의 질문이 학생의 모호한 이해를 명시화 → "무엇을 모르는지" 자체를 알게 된다
산출물 + 지속 효과
  • CLAUDE.md (프로젝트 루트)
  • 인터뷰 퍼스트 프롬프트 키트
  • 새 모듈·도메인 추가 시 동일 패턴 반복 → 신입 온보딩 시간 단축

💡 워크숍에서 만든 CLAUDE.md + /init 패턴의 결과 콘셉트입니다

02 / 05

스펙 우선 개발

정의 변경 전에 OpenSpec으로 명세를 만들고, AI가 명세를 컨텍스트로 코드를 생성한다
현재의 마찰

스펙은 항상 outdated. 작성 시간 부족, 결국 코드가 진실의 원천이 되고, 합류한 팀원은 코드를 읽어 추측한다.

AI Level Boost
  1. Friction 제거: openspec init이 기존 코드에서 스펙을 역추출
  2. openspec propose로 변경 제안을 생성 → 같은 스펙이 테스트·문서·코드리뷰의 공통 컨텍스트
  3. 스펙↔코드 드리프트를 AI가 자동 감지
  4. 🎓 학습 가속: 시니어도 처음 보는 OpenSpec 도구를 AI 페어와 4시간 안에 실전 사용
산출물 + 지속 효과
  • OpenSpec 스펙 디렉토리 (openspec/specs/)
  • Claude 스킬 (.claude/skills/) — 팀이 호출 가능
  • 문서 노후화 비용 자체가 사라진다

💡 워크숍에서 만든 OpenSpec + Claude 스킬 패턴의 결과 콘셉트입니다

03 / 05

자동화 테스트 + 코드 품질

정의 AI가 사양 기반 테스트와 린트 설정을 작성, 사람이 검수, Makefile로 한 줄 실행
현재의 마찰

설문 47%가 테스트를 최대 병목으로 답했다. 시간 부족으로 작성을 미루고, 작성된 테스트도 사양과 동기화 안 됨. 린트 설정도 프로젝트 초기에 잡고 끝나면 진화하지 않는다.

AI Level Boost
  1. Friction 제거: OpenSpec 스펙을 컨텍스트로 → AI가 '사양 기반' 테스트 생성
  2. Human-in-the-loop 검수가 환각 우려(87%)에 직접 대응
  3. 린트 룰도 AI가 코드를 보고 적합한 셋업을 제안
  4. 🎓 학습 가속: 검토 과정에서 AI의 추론을 따라가며 학생이 테스트 설계 감각을 빠르게 체화
산출물 + 지속 효과
  • 단위 테스트 · E2E 테스트 · 린트 설정 · Makefile
  • 커버리지 ≥80%
  • 새 기능마다 동일 패턴 반복 → 팀 전원이 같은 출발선

💡 워크숍에서 만든 OpenSpec + Makefile 패턴의 실행 결과 콘셉트입니다

04 / 05

품질 게이트

정의 pre-commit / pre-push hook이 로컬에서 즉시 품질 검증을 강제한다
현재의 마찰

설문 33%가 CI 자동화 검사가 거의 없다고 답했다. 검사가 PR 머지 후나 배포 직전에 처음 발견되고, 33% 팀은 PR 자동 품질 게이트도 활용하지 않는다.

AI Level Boost
  1. Friction 제거: AI가 03에서 만든 린트·테스트를 hook 스크립트로 묶어준다
  2. pre-commit이 커밋마다 린트+단위 테스트, pre-push가 푸시 시 E2E+커버리지
  3. 복잡한 CI 파이프라인 없이 워크숍 직후 적용
  4. 🎓 학습 가속: hook 동작을 통과/차단 양방향으로 시연해 학생이 게이트의 의미를 실전 체득
산출물 + 지속 효과
  • .git/hooks/pre-commit · .git/hooks/pre-push
  • 훅 공유 스크립트 (팀 배포용)
  • 코드 품질이 사람에 의존하지 않고 프로세스에 의존

💡 워크숍에서 만든 Git Hooks 패턴의 결과 콘셉트입니다

05 / 05

팀 확산 플레이북

정의 워크숍 경험을 튜토리얼·전환 계획서로 패키징해 팀 전체로 확장하는 활동
현재의 마찰

한 명이 워크숍을 다녀와도 팀 전체가 같은 패턴을 따르기까지는 별개. 보통 다시 잊혀지고, 도입은 한 사람의 영웅적 노력에 의존한다.

AI Level Boost
  1. Friction 제거: Claude Code 세션 로그를 분석해 튜토리얼 자동 생성
  2. generate-plan 스킬이 팀 실무 환경에 맞춤 전환 계획서 생성
  3. Claude 스킬로 패키징해 누구나 같은 패턴 호출
  4. 🎓 학습 가속: 팀원 각자가 미니 워크숍 형식으로 AI와 따라하며 학습 가속
산출물 + 지속 효과
  • 튜토리얼 문서 · migration-plan.md
  • 팀용 Claude 스킬
  • 4주 안에 팀 전원이 동일 워크플로우로 수렴

💡 워크숍 마무리 활동에서 만든 튜토리얼 + migration-plan 패턴의 결과 콘셉트입니다

AI를 믿을 수 있게 만드는 두 가지 패턴

컨텍스트 부족과 환각 우려를 구조적으로 해결하면서, 동시에 개발자 학습을 가속한다

인터뷰 퍼스트 패턴

"써줘"가 아니라
"나에게 질문해줘"
↓

컨텍스트 부족(60%) 구조적 해결.

🎓 학습 가속: AI의 질문이 학생의 모호한 이해를 명시화 → "무엇을 모르는지" 자체를 알게 된다.

Human-in-the-loop 검증

AI 생성 →
사람 검토 → 실행 → 피드백
↓

환각 우려(87%) 직접 대응.

🎓 학습 가속: 검토 과정에서 AI의 추론을 학습 → 다음에는 더 빠르게 판단한다.

87%의 개발자가 'AI 환각'을 우려한다. 답은 '더 똑똑한 AI'가 아니라 '환각을 잡아내는 프로세스'다 — 그리고 그 프로세스는 학습도 가속한다.

이 두 패턴은 워크숍에서 단순히 설명되는 게 아니라 시연됩니다. 시니어 개발자가 처음 보는 OpenSpec·Claude Skill·Git Hooks를 AI와 함께 4시간 안에 자기 코드에 적용 — 워크숍 자체가 라이브 데모입니다.
